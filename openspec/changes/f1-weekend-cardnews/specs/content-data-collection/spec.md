# Spec: content-data-collection

## ADDED Requirements

### Requirement: 수치 데이터는 API에서만 취득
순위, 랩타임, 포인트, 그리드, 등락 등 모든 수치 데이터는 Jolpica-F1 또는 OpenF1 API 응답에서 직접 바인딩되어야 하며(MUST), LLM이 수치를 생성·보정해서는 안 된다(MUST NOT).

#### Scenario: 퀄리파잉 결과 카드 데이터
- **WHEN** 일요일 아침 퀄리 결과 카드를 생성
- **THEN** 드라이버명·순위·랩타임은 Jolpica qualifying 응답 값이 그대로 사용된다

### Requirement: 요일별 레시피 데이터 세트
시스템은 콘텐츠 타입별로 다음 데이터 세트를 수집·정형화해야 한다(SHALL):
- 프리뷰(목): 트랙 정보(정적 JSON), 작년/올해 타이어 컴파운드, 최근 해당 GP 이슈 요약, 당시 포디움 (스프린트 주간이면 스프린트 포디움 추가)
- 관전 가이드(금): KST 변환 세션 시간표, 팀별 드라이버 라인업(FP1 대타 반영)
- 토(일반): FP1·FP2 결과 / 토(스프린트): FP1 요약 + 스프린트 퀄리 결과
- 일(일반): 퀄리 결과(Q3, Q1·Q2 탈락), 페널티 반영 그리드 / 일(스프린트): 스프린트 결과·이슈·Fastest Lap, 순위 등락, 퀄리 결과, 그리드
- 총정리(월): 레이스 Top 10, 이슈 + Fastest Lap, DOTD, 상위권 타이어 스틴트, 드라이버/컨스트럭터 순위 등락

#### Scenario: 비스프린트 토요일
- **WHEN** 어제 FP1·FP2가 종료된 비스프린트 주간
- **THEN** OpenF1에서 두 세션의 드라이버별 베스트랩을 집계한 순위 데이터가 준비된다

### Requirement: 순위 등락 계산
시스템은 드라이버/컨스트럭터 챔피언십 등락을 이번 세션 반영 후 순위와 직전 시점 순위의 비교로 계산해야 한다(SHALL). 스프린트 포인트 반영분도 동일하게 처리한다.

#### Scenario: 레이스 후 등락
- **WHEN** 월요일 총정리 카드를 생성
- **THEN** 각 드라이버·팀에 대해 순위 변동(▲n/▼n/—)이 직전 라운드 스탠딩 대비로 표기된다

### Requirement: LLM 요약 텍스트의 검수 플래그
LLM 웹서치로 생성되는 텍스트(최근 GP 이슈, 타이어 컴파운드, DOTD, 레이스 이슈 요약)는 검수 필요 플래그와 함께 승인 단계로 전달되어야 한다(SHALL).

#### Scenario: 이슈 요약 카드 승인 요청
- **WHEN** LLM이 작년 GP 이슈 요약을 생성
- **THEN** 텔레그램 승인 메시지에서 해당 카드가 "검수 필요(LLM 생성)" 표시와 함께 전송된다

### Requirement: 데이터 미반영 시 발행 중단
어제 세션의 결과 데이터가 아직 API에 반영되지 않았으면(빈 응답 또는 직전 라운드와 동일 데이터) 시스템은 발행을 중단하고 텔레그램으로 알려야 한다(SHALL). 오래된 데이터로 발행해서는 안 된다(MUST NOT).

#### Scenario: Jolpica 반영 지연
- **WHEN** 월요일 09:00 KST에 어제 레이스 결과가 아직 API에 없음
- **THEN** 발행 없이 "데이터 미반영 — 수동 재실행 필요" 알림이 전송된다
