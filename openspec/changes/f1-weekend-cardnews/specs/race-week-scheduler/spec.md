# Spec: race-week-scheduler

## ADDED Requirements

### Requirement: 매일 아침 레이스 주간 판별
시스템은 매일 09:00 KST에 Jolpica-F1 캘린더를 조회하여 오늘이 레이스 주간 윈도우(FP1 전날 ~ 레이스 다음날)에 속하는지 판별해야 한다(SHALL). 속하지 않으면 아무것도 발행하지 않고 종료해야 한다(SHALL).

#### Scenario: 레이스 주간이 아닌 날
- **WHEN** 09:00 KST 트리거 시점에 오늘(KST)이 어떤 라운드의 주간 윈도우에도 속하지 않음
- **THEN** 워크플로우는 발행·알림 없이 정상 종료한다

#### Scenario: 캘린더 API 장애
- **WHEN** Jolpica 캘린더 호출이 실패하거나 빈 응답을 반환
- **THEN** 텔레그램으로 오류 알림을 보내고 발행을 중단한다

### Requirement: 세션 날짜 기준 요일 타입 판별
시스템은 고정 요일 오프셋이 아니라 캘린더의 각 세션 실제 일시(KST 변환)를 기준으로 오늘의 콘텐츠 타입을 결정해야 한다(SHALL): 프리뷰(=FP1 전날), 관전 가이드(=FP1 당일 아침), 그리고 "어제 KST에 종료된 세션"에 대응하는 결과 타입.

#### Scenario: 일반 유럽 라운드의 월요일
- **WHEN** 어제 KST 밤에 레이스가 종료됨
- **THEN** 콘텐츠 타입은 "레이스 총정리"로 결정된다

#### Scenario: 변칙 일정 (현지 토요일 레이스)
- **WHEN** 라스베이거스 GP처럼 레이스가 현지 토요일에 열림
- **THEN** 요일이 아닌 세션 일시 기준으로 판별하여 카드 누락·중복 없이 동일한 레시피 순서가 유지된다

### Requirement: 스프린트 주간 분기
시스템은 캘린더 응답의 Sprint 필드 존재 여부로 스프린트 주간을 판별하고, 스프린트 전용 레시피(토=FP1+스프린트 퀄리 결과, 일=스프린트 결과+퀄리+그리드)로 분기해야 한다(SHALL).

#### Scenario: 스프린트 주간 토요일 아침
- **WHEN** 해당 라운드에 Sprint 세션이 존재하고 어제 FP1과 스프린트 퀄리파잉이 종료됨
- **THEN** "FP1 요약 + 스프린트 퀄리 결과" 레시피가 선택된다

### Requirement: 공식 그랑프리 명칭 사용
시스템은 모든 카드·캡션에서 Jolpica의 공식 raceName을 사용해야 한다(SHALL). 임의 명칭(도시명 등)으로 대체하지 않는다.

#### Scenario: 동일 국가 복수 라운드
- **WHEN** 한 시즌에 스페인에서 두 라운드가 열림 (마드리드/바르셀로나)
- **THEN** 각 라운드는 API의 공식 명칭으로 구분되어 표기된다
