# Spec: approval-feedback-loop

## ADDED Requirements

### Requirement: 발행 전 텔레그램 승인 필수
모든 발행분은 카드 전체(번호 표기)를 텔레그램으로 전송하고 명시적 승인(✅)을 받은 뒤에만 인스타그램에 발행되어야 한다(MUST). 승인 없이 자동 발행되어서는 안 된다(MUST NOT).

#### Scenario: 승인 없이 대기
- **WHEN** 카드 세트가 전송되었으나 응답이 없음
- **THEN** 발행은 진행되지 않고 승인 대기 상태를 유지한다

### Requirement: 카드 단위 자유 텍스트 수정 지시
승인자가 ✏️ 수정을 선택하면 시스템은 자유 텍스트 수정 지시를 받아 LLM으로 `[{카드 번호, 지시}]` 형태로 파싱하고, 지목된 카드만 재생성해야 한다(SHALL). 지목되지 않은 카드는 변경 없이 유지한다(SHALL).

#### Scenario: 복수 카드 자연어 지시
- **WHEN** 승인자가 "1번 밈 약해, 베르스타펜 하품하는 걸로. 4번은 배경 어둡게"라고 응답
- **THEN** 1번과 4번 카드만 각 지시를 반영해 재생성되고 나머지는 그대로 재전송된다

#### Scenario: 파싱 불가 응답
- **WHEN** 수정 지시에서 카드 번호를 특정할 수 없음
- **THEN** 시스템은 재질문 메시지를 보내고 재생성을 수행하지 않는다

### Requirement: 카드 타입별 수정 방식
생성 이미지 카드의 수정은 기존 이미지 + 지시문의 Gemini 이미지 편집(i2i)으로, HTML 데이터 카드의 수정은 카피/파라미터 반영 후 재렌더링으로 수행되어야 한다(SHALL). 생성 이미지를 처음부터 다시 뽑아 연속성을 깨서는 안 된다(SHOULD NOT → MUST 완화: 레퍼런스 없는 재생성 금지).

#### Scenario: 밈 표지 수정
- **WHEN** 밈 표지에 대한 수정 지시가 파싱됨
- **THEN** 기존 표지 이미지가 레퍼런스로 첨부된 편집 요청이 수행된다

### Requirement: 수정 루프 상한
수정 루프는 발행분당 최대 3회로 제한되어야 한다(MUST). 초과 시 자동 중단하고 텔레그램으로 알린 뒤 수동 처리로 전환한다.

#### Scenario: 4번째 수정 요청
- **WHEN** 이미 3회 수정을 거친 발행분에 다시 수정이 요청됨
- **THEN** 루프가 중단되고 "수동 처리 필요" 알림이 전송된다
